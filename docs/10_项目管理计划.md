## 2 项目目标与范围

### 2.1 项目目标

建设一套面向高校共享自习室的智能座位预约与管理平台，实现座位资源**在线化、公平化、数据化**。分解为七个可度量目标：

| 编号 | 目标 | 验收要点 |
| --- | --- | --- |
| G1 | 在线预约 | 学生可按日期、时段、自习室在线选座 |
| G2 | 智能分配 | 按偏好（区域/电源/靠窗）加权评分推荐并分配 |
| G3 | 全生命周期管理 | 待签到→签到→使用→签退全流程线上化，超时自动违约 |
| G4 | 信用治理 | 违约扣分、履约加分、低分限约 |
| G5 | 满座候补 | 排队候补、空位自动递补并通知 |
| G6 | 数据可视化 | 热力图、使用率趋势、高峰时段、热门座位 |
| G7 | 消息通知 | 预约成功、违约、递补等站内通知 |

**扩展目标**：AI 助手（流式对话 + 座位推荐，只读边界）。

### 2.2 工作范围

**范围内（8 项任务）**：

1. 项目立项与仓库基线；
2. 需求分析与建模（用例图、数据流图）；
3. 概要设计（架构、模块、接口、数据库）；
4. 详细设计与前后端实现；
5. 数据库迁移与种子数据；
6. 测试（单元 / 接口 / 并发 / 构建）；
7. 课程文档编制与一致性复核；
8. 演示准备与答辩交付。

**范围外（明确排除）**：

- 在线支付、门禁硬件对接、短信网关等外部集成；
- 多校区/多租户部署；
- 移动原生 App；
- 浏览器兼容性矩阵全覆盖。

### 5.2 质量保障措施

1. **编码规范**：Go 分层（handler/service/repository）、统一响应结构、参数化 SQL；
2. **代码审查**：功能分支合并前由组长审查（见 3.3）；
3. **自动化测试**：`scripts/run_tests.ps1` 一键执行"单测 + 接口 + 并发"三层测试；
4. **持续集成**：GitHub Actions 在 `push`/`pull_request` 到 `main` 时自动执行后端构建与单测、前端构建；
5. **文档一致性**：每轮代码变更后复核需求/设计/测试文档口径，缺陷登记于 SSR-BUG-001。
