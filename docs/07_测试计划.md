## 1 引言

### 1.1 编写目的

本计划用于界定"智能共享自习室预约系统"的测试范围、测试策略、资源安排、进度与准入/准出标准，作为测试执行（见《系统测试报告》SSR-TEST-001）与测试用例设计（见《测试用例》SSR-TC-001）的输入。

预期读者：项目组长、开发人员、测试人员、课程设计指导教师。

### 1.2 项目背景

本项目为《系统分析与设计》课程设计课题，由 5 人小组自主开发，采用 Go 1.27 + Gin 后端、Vue 3 + Vite 前端、PostgreSQL 18 主库与 Redis 7 缓存/互斥层。技术栈与模块划分见《概要设计说明书》SSR-HLD-001 与《详细设计说明书》SSR-DD-001。

| 术语 | 说明 |
| --- | --- |
| 单元测试 | 针对函数/组件级逻辑的白盒测试，使用 Go 官方 `testing` 包与表驱动模式 |

## 2 测试目标与范围

### 2.1 测试目标

1. 验证 FR-01~FR-15 功能需求与 M1~M10 模块的业务逻辑正确性；
2. 验证预约状态机（六态）迁移的准确性与不可逆约束；
3. 验证高并发抢座场景下"绝不超卖"的数据一致性；
4. 验证 Redis 组件（缓存、分布式锁、限流、黑名单）的正确性与降级行为；
5. 验证权限隔离（学生/管理员）与令牌注销的安全性；
6. 验证前端生产构建可通过。

### 2.2 测试范围

**纳入范围**：

| 层次 | 覆盖对象 |
| --- | --- |
| 单元测试 | 自动分配评分、时段校验、缓存抖动、分布式锁、限流、JWT 黑名单、AI 客户端、配置解析 |
| 集成测试 | 认证、RBAC、房间座位、预约、生命周期、候补、信用、通知、统计、AI 会话、注销 |
| 并发测试 | 20 并发抢占同一座位 |
| 构建验证 | 前端 `npm run build` 生产构建 |

**排除范围**（本阶段不测试）：

1. 浏览器兼容性矩阵（仅在 Chrome/Edge 最新版人工验证）；
2. 移动端真机适配；
3. 真实外部网关（短信、企业微信）——系统设计上不依赖；
4. 第三方 AI 模型服务的输出质量（仅验证协议兼容与降级）。

### 2.3 准入与准出标准

**准入标准**：

- 后端 `go build ./...` 通过；
- PostgreSQL 与 Redis 容器 healthy；
- 数据库已执行 `001_init.sql` 与 `002_ai_assistant.sql` 迁移及种子数据。

**准出标准**：

| 指标 | 要求 |
| --- | --- |
| 单元测试通过率 | 100% |
| E2E 用例通过率 | 100% |
| 并发测试防超卖 | 成功数严格 = 1，冲突数 = 19，5xx = 0 |
| 遗留缺陷 | 无致命/严重级未关闭缺陷 |
| 前端构建 | Build Success |

## 3 测试策略

### 3.1 总体策略

采用"三层测试"体系，由内向外逐层验证：

```text
第 1 层  单元测试（白盒）——Go testing + miniredis，验证纯函数与组件逻辑
第 2 层  接口端到端测试（黑盒）——Python 标准库，验证真实 HTTP 业务闭环
第 3 层  并发与性能测试——多线程瞬时请求，验证互斥与延时分布
```

### 3.2 各层策略说明

#### 3.2.1 单元测试

- **框架**：Go 官方 `testing`，表驱动（table-driven）模式；
- **替身**：Redis 依赖使用 `miniredis` 内存替身，避免测试环境依赖真实 Redis；
- **重点**：纯函数与确定性逻辑（评分、校验、抖动、锁属主校验）；
- **不测**：需要真实数据库的 repository 层（由 E2E 覆盖）。

#### 3.2.2 接口端到端测试

- **工具**：`scripts/test_api_e2e.py`，仅使用 Python 标准库 `urllib`，无第三方依赖；
- **范围**：23 项断言覆盖 10 大业务模块，含正向流程与逆向安全拦截；
- **数据**：使用种子账号 `admin/admin123`、`stu01`~`stu02 / 123456`；
- **特征**：每个用例独立断言，失败不中断后续执行，末尾输出通过率与耗时。

#### 3.2.3 并发与性能测试

- **工具**：`scripts/test_concurrency.py`，`concurrent.futures` 20 线程；
- **凭据**：用标准库 `hmac` 直接签发 HS256 JWT，绕开登录限流，保证瞬时并发；
- **断言**：成功=1、冲突=19、异常=0；
- **采集**：最小/平均/P95/最大响应时间与总耗时；
- **清理**：测试结束自动取消成功创建的预约，保持数据库整洁。

### 3.3 测试类型矩阵

| 测试类型 | 是否执行 | 说明 |
| --- | --- | --- |
| 功能测试 | 是 | 由 E2E 用例覆盖 |
| 边界值测试 | 是 | 时段边界：8h 上限、15 分钟非法粒度、起止时间相等 |
| 异常/逆向测试 | 是 | 401/403/404/409/429 场景 |
| 并发测试 | 是 | 20 并发抢座 |
| 性能测试 | 部分 | 仅采集并发场景延时，未做全接口压测 |
| 安全测试 | 是 | RBAC 越权、令牌注销、SQL 注入防护（参数化设计审查） |
| 兼容性测试 | 否 | 本阶段排除 |
| 恢复性测试 | 是 | Redis 离线降级行为（单元测试覆盖） |

## 7 风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 测试环境 Redis 未启动 | 限流/锁/黑名单用例失败 | 按 `docker compose ps` 确认 healthy 后再测 |
| 端口被占用（8080/5433/6380） | 后端无法启动 | 使用 `.env` 的 `STUDYROOM_HOST_PORT` 覆盖端口，并同步脚本 `BASE_URL` |
| 脚本 `BASE_URL` 端口与实际不一致 | 全部 E2E 用例连不上 | 执行前核对并修改脚本常量 |
| 种子数据被改动 | 并发用例座位号冲突 | 重置数据库：`docker compose down -v && docker compose up -d` |
| AI 密钥未配置 | AI 功能无法演示 | 未配置时系统降级，其他功能不受影响；演示前补 `.env` |
| 并发测试残留预约数据 | 影响后续用例 | 脚本已内置自动取消清理 |
