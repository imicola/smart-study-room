## 1 测试概述

### 1.1 编写目的
为全面验证“智能共享自习室预约系统”各项功能、性能指标、并发安全性以及高可用降级能力，检验系统是否符合《需求规格说明书》及《概要/详细设计说明书》中界定的业务规则与设计要求，特编写本系统测试报告。本文档为系统定稿验收与答辩交付提供真实可复现的质量证据。

### 1.2 测试范围
测试覆盖系统的三大主体层级：
1. **算法与模块单元测试**：针对自动分配加权评分纯函数、预约时段边界校验、Redis 旁路缓存与防雪崩抖动机制、分布式互斥锁（竞争/续租/降级）、IP/用户访问限流中间件等核心逻辑进行白盒测试；
2. **REST API 接口与端到端集成测试**：覆盖游客鉴权、学生选座预约、全生命周期状态机流转（签到/临时离开/返回/签退/违约）、满座候补排队与递补、信用流水核对、站内通知、运营热力图聚合等完整业务闭环；
3. **高并发抢座与防超卖压力测试**：模拟多用户瞬时高并发请求同一房间同一座位的极值场景，验证分布式锁与数据库排除约束的互斥有效性及 P95 响应延时。

## 4 高并发抢座与防超卖性能测试

### 4.1 测试场景设计
- **测试模型**：瞬间高并发场景（20 线程瞬时发起请求）。
- **抢座目标**：20 个已激活学生账号（`stu11` ~ `stu30`，各自拥有合法的独立 JWT）在同一毫秒发起 HTTP 请求，目标抢占 **1F-静音自习室 12 号座位（2026-09-28 14:00 - 16:00）**。
- **保护体系**：
  1. 接入层：Redis 分布式锁 `studyroom:lock:seat:12:2026-09-28` 拦截重复进入；
  2. 持久层：PostgreSQL 物理排他约束 `EXCLUDE USING gist (seat_id WITH =, res_date WITH =, tsrange(...) WITH &&)` 提供原子绝对一致性。
- **判定标准**：
  - 必须且仅能有 **1 个请求成功**，返回 HTTP 200 OK；
  - 剩余 **19 个请求全部拦截**，返回 HTTP 409 Conflict（“该座位此时段已被预约”）；
  - 数据库中对应时段仅生成一条合法记录，超卖数量严格为 0。
